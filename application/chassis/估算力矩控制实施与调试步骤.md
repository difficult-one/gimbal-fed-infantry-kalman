# 底盘估算力矩闭环实施与调试步骤

## 1. 当前实现结论

当前工程已经具备“目标底盘力 -> 四轮电流 -> 实际电流估算力反馈”的估算力矩链路。键盘力控使用 `CHASSIS_CONTROL_TORQUE`；`CHASSIS_CONTROL_FORCE_TRACK` 仅保留给真实轮端力传感器。

当前控制链路为：

```text
图传 W/A/S/D、鼠标
    -> fx_ref/fy_ref/mz_ref
    -> 力目标前馈 + 力误差 PI 修正
    -> 四轮雅可比分配
    -> 轮端力/电机扭矩/原始电流换算
    -> M3508/C620 电流环
    -> real_current 实际电流
    -> 电流估算轮端力和底盘合力
    -> 下一周期力反馈
```

当前关键代码：

- `application/cmd/robot_cmd.c:304`：键盘力控选择 `CHASSIS_CONTROL_TORQUE`；
- `application/chassis/chassis.c:431`：真实力跟踪只接受有效轮端力传感器，不再回退到电流估算力；
- `application/chassis/chassis.c:511`：目标力前馈加力误差 PI 修正；
- `application/chassis/chassis.c:445`：四轮力分配、电流换算、限流和参考输出；
- `application/chassis/chassis.c:319`：发布实际电流、轮端估算力和 `Fx/Fy/Mz`；
- `application/robot_msg.h`：力反馈话题和反馈来源定义。

必须区分两种闭环：

1. **当前可用：电机输出力估算闭环**。反馈来自 M3508 的 `real_current`，能够闭环控制电机扭矩的估算值。
2. **严格的地面接触力闭环**。必须接入轮端力传感器。电流估算不能消除轮胎摩擦、减速箱效率、打滑、坡度和负载变化带来的误差。

因此，当前没有轮端力传感器时，文档和日志应称为“基于电流估算的力矩闭环”，不能称为精确接触力闭环。

## 2. 当前模式和按键

### 2.1 速度模式

图传换挡键未开启时：

```c
control_mode = CHASSIS_CONTROL_VELOCITY;
```

此时：

- `W/S` 控制 `vx`；
- `A/D` 控制 `vy`；
- 电机运行速度环；
- `fx_ref/fy_ref/mz_ref` 被清零。

### 2.2 力反馈模式

图传换挡键开启时：

```c
control_mode = CHASSIS_CONTROL_TORQUE;
```

此时：

- `W/S` 产生 `fx_ref`；
- `A/D` 产生 `fy_ref`；
- 鼠标 X 产生 `mz_ref`；
- `vx/vy/wz` 被清零；
- 力环使用“目标力前馈 + 实际力误差 PI 修正”。

当前参数位于 `application/cmd/robot_cmd.c`：

```c
VIDEO_FORCE_X_STEP = 60.0f;
VIDEO_FORCE_Y_STEP = 60.0f;
VIDEO_FORCE_MAX = 80.0f;
VIDEO_FORCE_MZ_SCALE = 0.05f;
VIDEO_MZ_MAX = 5.0f;
```

标准 VT02 协议使用 `G` 键作为换挡键；解析器同时兼容旧协议的 `reserved bit0`。换挡使用上升沿计数，不能通过长按重复快速切换。

### 2.3 零力的含义

力控模式下松开所有按键时，目标力为零，电机不会主动提供持续驱动力。这是力控的正常定义，不等同于速度模式下的“零速保持”。

如果需要松手后保持位置、抵抗人为推动或限制速度，应使用速度环、阻抗控制或导纳控制，不能把零力目标当成零速目标。

## 3. 上电前工程检查

确认以下内容后再接触地面测试：

- 四个电机型号为 M3508；
- CAN ID 映射为 LF=1、RF=4、LB=2、RB=3；
- `WHEEL_BASE`、`TRACK_WIDTH` 使用实测值；
- `RADIUS_WHEEL` 使用实际接触半径；
- `REDUCTION_RATIO_WHEEL` 与减速箱一致；
- 底盘轮型和 `CHASSIS_DRIVE_OMNI_X` 配置一致；
- 电机反馈在线，`DaemonIsOnline()` 不反复掉线；
- 急停和 `CHASSIS_ZERO_FORCE` 可用；
- 单板或双板两端使用相同的 `Chassis_Ctrl_Cmd_s` 结构体和协议版本。

当前初始换算参数在 `chassis.c` 顶部：

```c
FORCE_DRIVE_EFFICIENCY = 0.85f;
FORCE_MOTOR_KT_NM_PER_A = 0.30f;
FORCE_CURRENT_RAW_PER_A = 16384.0f / 20.0f;
FORCE_CURRENT_LIMIT_RAW = 8000.0f;
```

这些是调试初值，不是已经完成实车标定的最终参数。

## 4. 调试顺序

必须按以下顺序进行，不能直接把力上限调大后落地测试。

### 第一步：编译和烧录确认

1. 完整编译工程，确认没有编译错误。
2. 烧录最新 `build/basic_framework_ATYPE.bin` 或 `.hex`。
3. 确认调试器下载的是当前工程生成文件，不是旧目录中的旧固件。
4. 复位后观察 RTT，确认没有连续 CAN、协议或电机掉线错误。

### 第二步：速度模式基线

1. 底盘架空，换挡键关闭。
2. 短按 W、S，确认前进和后退方向正确。
3. 短按 A、D，确认横移方向正确。
4. 松开按键，确认速度参考回到零。
5. 触发急停，确认四个电机停止。

方向错误时先修复速度模式的电机顺序、反向标志或 `OmniCalculate()`，不要在力控模式中用负号掩盖问题。

### 第三步：确认换挡和命令字段

在 RTT 或调试器中确认：

```text
速度模式：control_mode = CHASSIS_CONTROL_VELOCITY
估算力矩模式：control_mode = CHASSIS_CONTROL_TORQUE
```

力控模式下：

- 无按键时 `fx_ref=0, fy_ref=0, mz_ref=0`；
- 按 W 时只有 `fx_ref` 变化；
- 按 A 时只有 `fy_ref` 变化；
- 鼠标 X 变化时 `mz_ref` 变化；
- `vx/vy/wz` 应保持为零。

如果图传估算力矩模式不是 `CHASSIS_CONTROL_TORQUE`，说明烧录的不是当前代码，或图传换挡键没有被正确解析。

### 第四步：架空零输入测试

1. 底盘架空，所有轮子保持安全距离。
2. 进入力控模式，不按 W/A/S/D，不移动鼠标。
3. 观察：

```text
current_ref[4]
current_feedback[4]
wheel_force[4]
fx/fy/mz
```

期望结果：

- 目标力为零；
- 四路电流参考接近零；
- 实际电流只保留小范围噪声；
- 估算 `Fx/Fy/Mz` 接近零。

注意：零力模式下轮子可以被手动转动，这是控制定义决定的，不是电机掉线。若需要“松手后有力气”，应另行实现零速阻抗或速度阻尼。

### 第五步：单轴小力方向测试

首次测试建议临时把 `VIDEO_FORCE_MAX` 降到 `3.0f`，`VIDEO_MZ_MAX` 降到 `0.3f`。

#### Fx 方向

1. 架空底盘，进入力控模式。
2. 短按 W，不超过 0.2 秒。
3. 记录四路 `current_ref`、`current_feedback` 和 `fx`。
4. 松开 W，确认参考值回落。
5. 短按 S，确认四路电流整体反向，`fx` 也反向。

#### Fy 方向

使用 A/D 重复上述步骤，确认 `fy` 正负和底盘左右方向一致。

#### Mz 方向

1. 只给鼠标 X 很小的位移。
2. 检查四轮电流组合和 `mz` 正负。
3. 鼠标 X 同时会影响云台 yaw，必要时固定云台或暂时屏蔽云台 yaw 影响。

方向错误时检查雅可比矩阵行顺序、CAN ID、轮子安装方向和电机反馈符号，不要直接把 `Kt` 改成负数。

### 第六步：验证力反馈闭环

RTT 日志格式为：

```text
[CHASSIS_FORCE] ref=a,b,c,d fb=e,f,g,h force=fx,fy,mz
```

其中：

- `ref`：四个电机的原始电流目标；
- `fb`：四个电机的实际电流反馈；
- `force`：底盘估算力乘以 100 后打印，实际值需除以 100。

测试 W 时应满足：

1. `ref` 很快到达由 `fx_ref` 分配出的四路目标；
2. `fb` 跟随 `ref`，不能长期偏差很大；
3. `force` 的 Fx 方向与目标一致；
4. Fy 和 Mz 在纯 Fx 测试中应接近零；
5. 松开 W 后 `ref/fb/force` 回到零附近。

如果 `ref` 正确但 `fb` 长期偏低，检查供电、电机反馈、C620 限流和机械负载。如果 `fb` 跟随良好但实际地面推力不一致，问题在 `Kt`、效率、轮半径、摩擦或打滑，不能靠继续调电流 PID 解决。

### 第七步：电流和力矩参数标定

#### 原始电流比例

当前初值为：

```text
I_A = I_raw / 819.2
```

用 C620/电机手册或可靠电流计确认 `FORCE_CURRENT_RAW_PER_A`。反馈和参考必须使用同一原始单位。

#### 转矩常数和效率

用推力计、已知力臂或砝码做至少 3 个工作点：

```text
T_motor = F_measured * r_wheel / (gear_ratio * efficiency)
Kt = T_motor / I_A
```

根据实测斜率更新 `FORCE_MOTOR_KT_NM_PER_A` 和 `FORCE_DRIVE_EFFICIENCY`。不要只用一个点拟合，也不要把空载电流直接当成有效牵引力。

#### 四轮一致性

给四个轮子相同的低电流指令，比较实际电流和估算轮端力。差异明显时先检查电机、减速箱、轮胎和机械阻力，再决定是否需要单轮比例补偿。

### 第八步：落地低力测试

架空测试全部通过后才落地：

1. 力上限从 2 到 5 N 开始；
2. 场地清空，旁边准备硬件急停；
3. 每次只短按 W/A/S/D 0.1 到 0.2 秒；
4. 观察运动方向、四路实际电流和 `Fx/Fy/Mz`；
5. 方向错误立即断电，回到架空测试修改矩阵或符号。

逐级增加到 10 N、20 N、40 N、60 N，每一级记录：

- 实际电流和估算力；
- 起步是否需要手动拨轮；
- 是否出现单轮先动、横摆或打滑；
- 电机、C620 和电源温升；
- 松开按键后是否正确回零。

### 第九步：验证真实传感器闭环（接入传感器后）

如果接入轮端力传感器，传感器必须发布 `chassis_force_sensor`，并满足：

```text
protocol_version = CHASSIS_FORCE_FEED_VERSION
force_source     = CHASSIS_FORCE_SOURCE_SENSOR
force_valid      = 1
sample_seq       每帧递增
```

传感器调试顺序：

1. 无载采集零点；
2. 逐个轮子施加已知载荷，标定比例和方向；
3. 验证传感器发布的 `wheel_force[4]`；
4. 验证由轮端力计算的 `Fx/Fy/Mz`；
5. 从小 `Kp`、`Ki=0` 开始做单轴力阶跃；
6. 确认无振荡后再逐步增加 `Ki`；
7. 测试重复力阶跃、纯平移、纯旋转和传感器断线。

传感器有效时，控制器优先使用传感器反馈；传感器无效、超时、序号不变或协议错误时必须停止力跟踪，不能继续使用最后一次有效力值。

## 5. 安全测试

### 急停

触发 `CHASSIS_ZERO_FORCE` 或遥控器急停，确认：

- 四个电机停止；
- `force_current_ref[4]` 清零；
- 力环 PID 清零；
- 解除急停后不会突然恢复上一帧力矩。

### 电机和 CAN 掉线

断开任意一个电机反馈或 CAN，确认底盘停止输出，不会继续使用旧电流目标。

### 图传掉线

停止图传发送，确认按键、鼠标和换挡状态不会保持上一帧，底盘进入安全状态。

### 协议错误

速度模式可以使用默认协议；力控和传感器模式必须检查协议版本。版本不一致时禁止进入力控。

### 过流和温升

堵转、低速大力和单轮离地时重点观察实际电流、C620 温度、电源压降和功率限制。达到限流或温度阈值时必须降额或停机。

## 6. 常见现象判断

| 现象 | 优先检查 |
| --- | --- |
| 力控模式像没上电 | 是否把零力误认为零速保持；零目标本来就不输出保持力 |
| 按键后必须手动拨轮 | 静摩擦大于当前目标力；检查力上限、参数标定和机械阻力 |
| 轮速越来越快 | 恒定力会产生持续加速度；需要速度阻尼、阻抗或导纳，不是电流滤波问题 |
| `ref` 正确、`fb` 很小 | CAN、电源、C620 限流、电机反馈或电机故障 |
| `fb` 正确、实测推力不对 | `Kt`、效率、轮半径、摩擦、打滑或负载模型错误 |
| 四轮方向不一致 | CAN ID、轮子顺序、反馈符号或雅可比矩阵错误 |
| `force` 有明显横向/旋转分量 | 四轮电流不一致、轮子安装角度错误或力矩臂参数错误 |
| 切换后突然冲击 | 模式切换没有清 PID、旧参考值未清零或协议字段错位 |

- `modules/motor/motor_def.h`：电机闭环类型和控制器配置。
