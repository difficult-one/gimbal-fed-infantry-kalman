# 卡尔曼底盘轮速与 IMU 观测一致性优化建议

适用范围为 **gimbal-fed infantry A - Kalman** 当前 frame18 源码与 2026-11-10 的 frame17 落地日志。当前默认 `MC_SHADOW`，卡尔曼估计和候选补偿在运行。frame18 新增的纯自旋逐轮微调会单独改变部分轮速参考，实车对比应先采集一份 frame18 基线。见[当前配置](../../config/config.c)和[第 40 次落地调试记录](调试记录/20261110_第四十次frame17落地纯旋转漂移分析.md)。

## 按顺序做的改动

| 优先级 | 改动 | 依据和完成条件 |
| --- | --- | --- |
| P0 | 校正回放参数和单位 | 已确认脚本可能用错历史轮径。相同输入和元数据应得到可重复的结果 |
| P0 | 传播 SPI 读状态，采集可对齐的原始样本 | 已确认驱动吞掉读错误。失败样本应有明确计数，高频记录应能重放 |
| P1 | 按有效时间配对观测，再验证杆臂和去重力链 | 已确认代码缺少信号延迟对齐。用同一段原始数据逐项比较残差 |
| P2 | 验证交点到底盘中心的三维转换 | 先测量参考点和底盘转动。只有证实平面模型不足时才扩展补偿 |
| P3 | 评估门控恢复、协方差及主动补偿 | 同时检查残差、故障保护和外部轨迹。融合有效率只是其中一个指标 |

## P0：先让日志和回放可信

**让回放使用采集时的配置。** [通用相位分析脚本](../../tools/analyze_spin_phase.py)和[通用工况分析脚本](../../tools/analyze_chassis_run.py)共用轮径映射，当前把 frame16/17 当作 **72.5 mm 半径**，而这批 frame17 落地日志使用 **76 mm 半径**。`--spin-ref-mradps` 只改变筛选参考转速。建议为每次采集保存固件标识、frame、配置标识、有效滚动半径、减速比、轮组几何、坐标约定和逐轮微调。回放优先读取这份配置，缺失或冲突时明确报错。frame17 专用统计脚本还把已经换算成 m/s 的数值写入 `wheel_odometry_n_velocity_mmps`，建议按实际单位更名并处理旧结果。见[专用统计脚本](../../tools/analyze_frame17_spin_drift.py)。

**在采样入口区分读成功、新样本和恢复。** `mpu_read_bytes()` 忽略两次 HAL SPI 返回值且恒返回 0，`mpu_get_data()` 会继续解析缓冲区。建议把失败状态传到上层，初始化和标定也只计入成功样本。运行时不把读失败当作新有效样本，并记录失败原因，沿用现有的时基与恢复机制。若板上能取得 DRDY，给样本打采集时间戳。否则将 SPI 完成时刻标为读取时间，并记录能识别的新样本信息。验收时注入超时、重复样本和采样间隙，检查姿态、刚体求导及底盘融合是否按各自的有效性规则处理。见 [MPU6500 驱动](../../modules/imu/mpu6500_spi.c)和 [INS 采样链](../../modules/imu/ins.c)。

**加一个短时高频抓取入口。** 用有界缓冲记录 IMU 原始三轴、样本序号和时间、姿态与重力向量、杆臂修正前后值、四轮原始与滤波反馈及其接收时间、yaw 编码器、门控原因。先记录再导出，避免每次采样都输出文本。沿用现有 `OBS.dv_now_mmps`、`dv_res_mmps`、`reject_reason`、`control_inhibit` 和 `RIGID` 汇总对照。10 Hz 文本适合看工况和门控趋势，高频时序与滤波只能靠原始样本验证。见[底盘日志输出](chassis.c)。

## P1：先对时间，再评估加速度处理

1. **用台架或短时实车数据辨识有效延迟。** 当前 MPU-6500 的 20 Hz 配置在手册上对应加速度 **19.8 ms**、陀螺仪 **9.9 ms**。驱动加速度注释写的是约 **8.9 ms**，建议依据手册修正注释并回读寄存器。中心加速度另有 **8.5 ms** 的软件低通时间常数。滤波响应随频率变化，手册数值和软件时间常数不能直接作为全链路固定补偿。见[驱动配置](../../modules/imu/mpu6500_spi.c)和 [MPU-6500 寄存器手册 Rev. 2.1，第 14～15 页](https://www.tinytronics.nl/product_files/001439_MPU-6500-Register-Map2%20%281%29.pdf)。
2. **先离线做同一时刻的对照。** 当前底盘用最新四轮反馈和当前航向做旋转，再用控制时刻积分 IMU，样本年龄检查无法处理滤波延迟。优先按共同有效时刻配对四轮速度、IMU 加速度和相应姿态、编码器，旋转到同一导航系后再算 `∫a dt − Δv`。通过回放后，再考虑在固件里用短历史缓冲实现有界插值。遇到缺样、时钟代际切换或超出历史范围时，保持相应的有效性检查。现有 **13.5 ms 相位超前**用于控制输出方向，另行评估。见[底盘估计与控制](../../modules/chassis_motion/chassis_motion.c)。
3. **分开验证杆臂修正和姿态去重力。** 先回放同一原始序列，逐项比较加速度计与陀螺仪的时间对齐、20 ms 拟合求导、重力投影，记录每项对残差的影响。先用固定底盘的俯仰动作验证云台 IMU 到轴交点，再用有外部参考的平移验证去重力。若确认求导在实测频段放大了扰动，再调整频响并检查启停响应。姿态误差约 **1°** 时，可产生约 **0.17 m/s²** 的水平重力残差。见[刚体补偿](../../modules/imu/imu_compensation.c)和[姿态估计](../../modules/algorithm/quaternion_ekf.c)。

run1 的 10 Hz 日志粗略对照中，把 IMU 前移 20 ms 只让 0.25 秒积分残差 RMS 从约 0.068 降至 0.064 m/s。在另一个近恒轮速区间（681.87～682.37 秒），两者的速度增量相差 **0.121 m/s**。因此实车复测要同时覆盖启停和稳态，按高频数据辨识延迟。

## P2：确认参考点与轮地运动

INS 的三维杆臂把观测换算到 yaw/pitch 轴交点。底盘端再用 `yaw_center_m[2]` 和 yaw 角速度、角加速度处理轴交点到轮组中心的水平偏置。当前水平偏置为零，第二段没有高度和底盘俯仰、横滚项。若交点有高度差，底盘摇摆时就可能产生轮式平面模型未覆盖的水平加速度。见[底盘参考点转换](../../modules/chassis_motion/chassis_motion.c)和[机械参数](../../config/config.c)。

先测轴交点相对轮组中心的三维偏置。落地自旋时用固定机位标记中心与航向，并测底盘本体俯仰、横滚。云台稳定时的陀螺读数不能代替底盘角速度。若实测支持三维转换，在同一坐标系按对应刚体的 `α × r + ω × (ω × r)` 补齐，并用已知几何的合成数据检查符号和退化到平面时的结果。轮地滑移和实际漂移用外部轨迹与四轮跟踪一并核对。

## P3：按同一口径验收

- **比较残差和保护。** 现有 0.25 秒窗口的残差上限为 **0.04 m/s**，等效持续偏差约 **0.16 m/s²**。超限可提前拒绝并重启窗口。此检查先于 KF 更新，改 `R` 不会放行已被门控拒绝的观测。先保持相同门限做对照，再根据独立实测结果评估是否需要改门控。见[门控实现](../../modules/chassis_motion/chassis_motion.c)和[阈值配置](../../config/config.c)。
- **回放和实车各验一次。** 使用同一份高频序列逐项比较二维积分残差 RMS、P95、拒绝原因、`accel_used`、`valid` 和恢复耗时。实车在 SHADOW 下重复静止俯仰、直线启停与匀速、正反向落地自旋，核对外部中心轨迹和四轮跟踪。frame17 三段稳定自旋的融合有效帧分别为 **8/444、18/444、4/446**，高频中心加速度 RMS 分别约 **0.81、0.88、0.80 m/s²**，可作为历史参照。原始数据见 [frame17 落地日志](../../build/frame17_ground_drift_20261110/)。
- **复用现有测试。** PowerShell 下运行 `./tests/run_chassis_motion_tests.ps1`（需要 GCC）。现有用例覆盖刚体补偿、采样差分、时基恢复、观测门控和主动许可。新增时序逻辑时，重点补可控延迟、异步采样、断流恢复的用例。现有 `chassis_motion_delay_test.c` 验证控制输出的相位超前，传感器对齐需要自己的回放用例。见[主机测试入口](../../tests/run_chassis_motion_tests.ps1)。
- **按条件进入主动测试。** 在重复落地工况中确认残差确实降低、外部运动估计更准，且异常数据仍能撤销许可后，再按工况评估主动补偿。保留对 `cmd_g-ref_g`、`control_ready` 和异常退出的检查。

## 现有日志的复核命令

在项目根目录执行以下命令可查看第 4 段落地日志的完整帧、门控和 IMU 诊断。两条命令默认输出到终端。通用审计中的稳定自旋子统计还沿用旧的 8162 mrad/s 筛选值，本批 6892 mrad/s 自旋应参考专用汇总。

```powershell
python -B .\tools\audit_chassis_text.py .\build\frame17_ground_drift_20261110\run4_ground_spin_position_20261110.txt
python -B .\tools\analyze_imu_diagnostics.py .\build\frame17_ground_drift_20261110\run4_ground_spin_position_20261110.txt
```

专用汇总见 [run1～3 统计](../../build/frame17_ground_drift_20261110/analysis.json)和 [run4 统计](../../build/frame17_ground_drift_20261110/run4_analysis.json)。这些汇总来自文本快照及秒级 IMU 统计。P1 所需的逐样本算法回放需要新的高频采集。
