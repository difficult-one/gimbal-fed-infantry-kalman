# 2026-10-27 滤波时序与 YAW 残余零偏修复

固件标识 `fw=20261027`，YAW 日志 `diag=2`。本次已修改源码并完成 ARM 编译、主机数学/回归测试；实车效果尚需烧录验证，不能把仿真结果当作实测验收。

## 实际改动

### 1. 杆臂校正回到 INS 同一采样链

旧链在 INS 中先以 8.5 ms 时间常数低通加速度，再在 200 Hz 底盘任务中对抽取的导航系角速度差分，直接扣除未经同样低通的杆臂项。因此即使安装参数正确，加速、反向和陀螺噪声也会在两条路径之间形成残差。

现在每次 INS 原始采样（任务目标约 1 kHz）执行：

1. 使用同帧四元数去重力，得到尚未软件低通的机体系运动加速度。
2. 用连续 INS 时间戳计算三轴角加速度。机体系角速度的导数就是机体系角加速度，因为旋转附加项 omega×omega 为零；避免对 EKF 修正后的导航系角速度再差分。
3. 扣除 `alpha_b×r_b + omega_b×(omega_b×r_b)`，包含 YAW/PITCH 耦合及安装高度。
4. 再进行 8.5 ms 低通，通过完整四元数转入 INS 导航系，与本帧未校正加速度一起发布。
5. 底盘端只消费同帧校正结果并转换为 N=(x,-y,-z)，不再次执行该杆臂差分。

安装参数仍取传感器机体系 `(-0.084, 0, +0.037) m`，来自当前已确认的安装方向和尺寸。首帧、重复/超时采样、非法四元数、非有限输入或角加速度超过 100 rad/s² 时，撤销候选有效性并重新建立连续历史，不把异常值限幅后伪装为有效观测。

MPU6500 原陀螺 CONFIG=4 是 20 Hz，不是旧注释写的 41 Hz；加速度原 CONFIG_2=2 为不同带宽。现将加速度 CONFIG_2 改为 4，与陀螺同为 20 Hz，减少两传感器硬件延迟差。两者仍有约 1 ms 的标称延迟差，不能声称绝对同步。初始化表只遍历实际配置项，避免写入补零的空配置项。

主要源码：`modules/mpu6500/imu_compensation.c/.h`、`mpu6500.c`、`mpu6500driver.c`、`application/chassis/chassis_motion.c`。

### 2. 用完整精度编码器修正 YAW 残余零偏

启动标定结果保持独立。新增的 trim 是启动标定之外从机体系 gz 减去的残余零偏，不覆盖启动标定值，也不写 Flash。

只有下列条件同时满足才积累学习窗口：

- 遥控器在线，左开关在下（遥控模式），右开关在上（底盘不跟随），云台处于陀螺模式。
- 底盘为速控，平移/旋转命令为零，四轮在线且原始/滤波速度均接近零。
- 命令、底盘静止许可、IMU、YAW/PITCH 电机反馈都在 20 ms 内更新。
- 启动标定通过（cal=1），YAW 输入为零，YAW/PITCH 目标角保持不变；PITCH 编码器累计变化小于 0.15°。
- 加速度模长接近重力，角速度足够小，俯仰姿态远离航向奇异点。

先等待 2 s 连续满足条件，再每约 3 s 比较一次 `IMU 航向变化 - 编码器角变化`。使用电机原始浮点角、处理 0/360° 回绕，避免旧公共反馈截成整度。当前安装下两种角度变化同号，已有多次手动 YAW 日志验证。

通过四元数计算航向对机体系 gz 的灵敏度，考虑 PITCH 倾斜，按误差的一半更新 trim；单次更新不超过 0.001 rad/s，总量限制在 ±0.01 rad/s。窗口内实际编码器平均转速超过 0.75°/s 时取消学习，不把主动转动当作零偏。目标变化、转动或失联立即清除学习窗口并冻结已学值；恢复静止后重新等待。没有重置目标角、跳变四元数或修改 PID。

同一个 trim 同时用于姿态解算、云台速度反馈和杆臂计算，保持单位与数据来源一致。`INS_YAW_BIAS_AID_ENABLE=0` 可关闭此功能，恢复只使用启动标定。

该约束要求底盘相对地面确实静止。轮速为零不能识别整机被缓慢搬动/旋转，测试时应固定底盘；轮速和云台 IMU 仍不构成永久可观测的绝对航向系统。切入跟随、自旋、力控或图传模式会冻结学习，已有 trim 继续使用。

## 日志怎么读

仍只使用通道 0 可读文本，默认约 10 Hz。`fw=20261027` 确认版本；`diag=2` 表示本次字段语义。

| 字段 | 含义 |
| --- | --- |
| enc_mdeg | 完整精度单圈编码器角 ×1000；实际传感器分辨率约 0.044°，并非 0.001° |
| enc_t_us | 上述编码器原始 CAN 反馈时间，用于判断新鲜度 |
| bias_z_urps | 原始启动标定的 Z 零偏 ×1e6 rad/s，保留旧含义 |
| trim_z_urps | 新增额外残余零偏 ×1e6 rad/s，允许正负，不要求必须变为零 |
| trim | 0=条件不满足/冻结；1=等待或首次窗口积累；2=已经更新；3=修正达到限值 |
| trim_updates | 本次上电已完成的修正更新次数；正常静止时约每 3 s 增加一次 |
| corr | 本帧三维候选有效；不表示实车验收通过 |

YAW 诊断仍是低优先级日志读取时的独立快照，cmd_t_us、enc_t_us 与底盘 t_us 有各自来源，不能把五行当成所有数值严格同时测得。IMU 行的 nav_a 与 center_a 则来自同一份 INS 快照。

当前仍保持 `MC_ESTIMATE_ONLY`、`MC_IMU_ACCEL_VALIDATED=0`。`accel=0`、`valid=0`、轮速正常时 `exit=5` 是预期行为；本次自动修正的是 IMU 残余零偏，不代表自动开启底盘加速度融合。

## 已完成验证

执行 `tests/run_chassis_motion_tests.ps1` 和 `tests/test_motion_log_decoder.py` 均通过：

- 原有 KF、运动学、平面偏置、限幅、超时、失效恢复等回归通过，融合开/关均覆盖。
- 独立解析 YAW/PITCH/耦合轨迹在 1 kHz 经过新 INS 数学层、200 Hz 经过底盘核心；保留已知真实平移，非法样本撤销候选。
- 合成静止陀螺噪声场景，中心残差 RMS 从未滤波差分的约 0.0591 降为 0.0129 m/s²。
- 合成解析正弦 YAW 场景，软件滤波时序残差从约 0.002265 降为 0.000119 m/s²。
- 模拟闭环在正/负 0.0016 rad/s 残余零偏、水平和倾斜姿态、8192 格编码器量化/回绕下，估计收敛至已知偏置附近；真实慢转不会被强行归零。
- 目标变化、PITCH 变化、无效帧、断流、限幅及时间戳回卷检查通过。
- `ChassisMotionState` 仍为 444 字节，历史二进制帧仍为 456 字节，旧 20261016/20261026 版本解码兼容。

这些数字来自可重复的合成测试，不是对最近日志重算后的实车改善率。ARM 固件编译成功，仍有工程既存的未使用变量、libc 系统调用桩和 RWX 段警告。

## 烧录后按这个顺序验证

1. 烧录本次 `build/basic_framework_ATYPE.elf`，通道 0 确认 fw=20261027、diag=2。仍用文本窗口。
2. 左开关下、右开关上，固定底盘，松开所有摇杆，上电标定时也保持不动。持续读取并保存 60 s。
3. 首次满足条件约 5 s 后应看到 trim_updates 开始增加，trim 通常从 1 变为 2。重点看 enc_mdeg 是否在后半段趋稳，以及机械参照是否不再持续偏移；不要只看 IMU 反馈角。若 trim 一直为 0，先核对模式、cal=1、四轮在线、零输入和反馈时效。
4. 保留底盘固定，分别以约 20～30°/s 缓慢转 YAW 和 PITCH，反向前停 5 s，各段结束后再静止 10 s。转动时允许 trim 回到 0，修正量冻结；停稳后重新积累。
5. 比较同一 N 系下的补偿前/后加速度残差。确认 YAW 与 PITCH 都改善、静止不被噪声放大后，才能继续后续融合验收。本次未放开该开关。
