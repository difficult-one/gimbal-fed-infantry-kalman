# 第二十七次：frame14 时基恢复与观测门控改造

本次依据最新 frame12 日志暴露的时间冻结、断连恢复后大加速度残差及零轮速/KF残余速度问题修改代码。固件标识为 `fw=20261107 frame=14`，默认仍为 `mode=2 / MC_SHADOW`。尚未烧录或进行本次实车验收。

现车默认单板全向轮固件已生成：`build/basic_framework_ATYPE.elf`、`.hex`、`.bin`，独立目录 `build/frame14/` 也已更新。其余板型/轮型位于 `build/variants/<板型>_<轮型>/`，按实际硬件选择，勿将双板固件混用于单板现车。

## 1. 已实现的行为

1. `bsp/dwt/bsp_dwt.c` 使用 TIM14 驱动的 `HAL_GetTick()` 交叉检查 DWT：检查周期至少5 ms，允许2 ms的粗时钟/中断延迟差；保留最长1 s的比较基准，避免每次重建基准漏掉反复短暂停转。发现 TRCENA/CYCCNTENA 缺失时恢复使能，不清 CYCCNT；发现时间不一致时按粗时钟修复单调时间轴，递增generation并保存原因/寄存器。所有DWT读者共享临界区保护的逻辑周期，DeltaT及timeline使用同一时间轴。
2. `INS_Task` 检查时钟generation变化，即便当前dt已回到正常也拒绝跨故障更新。异常时发布新原始传感器、撤去有效位，保留最后姿态；不从加速度自动重新设置YAW/PITCH目标。
3. 启动或故障后，运动观测恢复需要连续500 ms满足：姿态EKF已收敛，未拒绝重力观测，卡方比在0～1，角速度幅值<0.05 rad/s，加速度模长距9.81小于0.3 m/s²，候选水平运动加速度幅值<0.10 m/s²。任一条件中断重新计时。恢复后允许正常动态，不把上述条件当作通用零速判据。
4. KF消费端新增0.25 s一致性窗口：`residual = integral(a_center_N) - (v_wheel_N_end-v_wheel_N_start)`；使用梯形积分，二维残差阈值默认0.04 m/s。IMU新采样积分、轮速新采样作为端点，允许两者不同频率；失效/过期/异常时间会重新建窗。首次一致性通过前不使用加速度初始化KF。
5. 窗口冲突时，加速度槽不进入KF，主动速度追加立即撤销，诊断KF从轮速和零加速度重新建立；估计有效位保持撤销，直到重新通过一致性窗口和原有20个联合有效样本。这里保留的是轮速诊断值，不是给地速强制定零，也没有认定轮速与IMU哪一个正确。

上述默认阈值是用于拒绝当前明显故障的工程初值，还需要用正常运动和噪声数据标定。窗口检查不能瞬时识别故障，运动中突然出现冲突可能在下一个窗口完成时才被拒绝；通过检查也不等于已有独立地速真值。

## 2. 新日志字段

原六行仍在，增加第七行 `[OBS]`，与 STATUS 同seq、同次入队。原 `ChassisMotionState` 444字节及历史二进制帧456字节不变；OBS使用独立小结构并排入队。旧的 `PopLog` 保留，新接口 `PopDiagnosticLog` 一次返回三份匹配快照。

| 字段 | 含义 |
| --- | --- |
| `imu_t_us / clock_gen` | 源IMU时间、底盘读取时的时钟修复代次；源码还检查源快照是否落后于当前代次 |
| `recovering / good_ms` | INS运动观测恢复是否挂起，以及连续合格样本累计毫秒 |
| `q_1e6` | 发布给运动链的单位四元数，乘1e6 |
| `gravity_mmps2` | 由本帧姿态预测的传感器机体系重力，mm/s² |
| `tilt_mrad` | 公共INS约定的PITCH/ROLL，mrad |
| `chi_x1000` | 姿态EKF卡方统计 / 阈值，乘1000；不是原始卡方值 |
| `att_flags` | 位0=已收敛，位1=姿态EKF稳定条件通过，位2=拒绝本次重力观测，位3=矩阵出错，位4=该源帧跳过姿态更新 |
| `innov_x1000` | `[vx,ax,vy,ay]`观测创新，各按其SI单位乘1000；有候选但被门控拒绝时也保留候选创新 |
| `r_x1e6` | KF实际配置的四个观测方差，顺序同上，乘1e6；槽是否使用由STATUS.obs判断 |
| `dv_res_mmps` | 最近完成一致性窗口的二维残差，mm/s；不是补偿命令 |
| `window_ms / gate / rejects` | 当前窗口进度；gate=0建窗、1一致、2冲突；冲突窗口累计数 |

`[CLOCK]` 随低频RIGID/AID诊断输出，有独立时间戳，不能与某条STATUS冒充同一采样时刻：

- `t_us / hal_ms / cyccnt`：读取时的逻辑时间、独立HAL毫秒计数和原始周期计数。
- `gen / flags / last_t_us`：修复代次、最近异常原因位、最近修复逻辑时间。
- `flags` 位0=TRCENA关闭，位1=CYCCNTENA关闭，位2=DWT/HAL时间不一致。
- `demcr / ctrl`：发生异常前的寄存器值保留到下一次异常；gen=0时显示当前值。因此它们不是修复完成后使能位的实时显示。

新增退出码 `exit=11` 为时钟代次变化，`exit=12` 为轮速/加速度窗口冲突；原 `exit=8` 继续表示恢复尚未完成。`valid=0` 时SHADOW/主动模式均不追加KF速度补偿；基础轮速环仍按原有有效命令运行，时间步长异常仍走原有零输出路径。

文本格式化在低优先级任务执行，每组七行一次非阻塞RTT写入，空间不足整组丢弃并累计tdrop；无高优先级逐帧printf或等待。解析器在frame14下要求OBS完整，不会把少了OBS的记录当作完整新固件帧。`audit_chassis_text.py` 汇总门控、恢复和非有限值，`analyze_imu_diagnostics.py` 解析CLOCK及原有RIGID/AID。

跳过姿态更新的无效源帧不沿用旧卡方统计冒充新结果：`att_flags=16`，卡方字段输出非有限值哨兵 `−2147483648`；姿态/重力保持最后结果但不可用于融合。正常源帧的卡方检验对应本次姿态预测创新，四元数和预测重力为本次更新后的发布量，二者处于同一IMU采样的不同计算阶段。

## 5. 时钟方案的边界

HAL tick来自持续运行的TIM14，分辨率1 ms，允许中断延迟。它能检查“任务/采样继续执行而DWT不走”的情况；修复不是还原丢失期间的微秒真值。若CPU被调试器完全暂停、HAL中断也暂停，两者都无法提供完整墙钟经过时间；若应用主动挂起TIM14 tick，也需要另接持续硬件时钟。不得仅凭generation未变化证明一次人工调试暂停没有发生。

本次没有自动从加速度重设四元数、自动清零车速或在线学习一组固定偏置。消除实车去重力残差的具体根因，仍需新版诊断和真实停止/位移对照来确认。
