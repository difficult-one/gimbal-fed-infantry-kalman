# 第三十三次：frame15 瞬态门控与姿态重捕获修复

已完成代码修改、主机回归、真实 INS/EKF 代码测试与九种板型/轮型 ARM 构建，生成 `fw=20261108 frame=15 mode=2` 固件。未执行硬件烧录；本报告中的新行为验证来自软件测试，实车效果尚待采集。

当前最大问题是**自旋时中心加速度与轮速速度变化持续不一致，已有门控又可能在瞬态冲突发生后延迟撤销权限**。本次修复错误放行路径，并限制一个可能把水平运动加速度误当重力的姿态恢复路径；不能据此认定实车加速度残差、所有跑偏或打滑已经解决。

## 1. 修改依据

上一轮 A/B 数据分析见[第三十二次报告](20261108_第三十二次AB落地验证与小陀螺融合拒绝分析.md)：

- A 的 seq40500：轮速重建速度幅值约0.00437 m/s，KF却给出约0.10249 m/s，X分量反向，仍为 `gate=1 valid=1`；下一记录才撤销权限。用户没有感觉到实车反向窜动，不能将这段估计直接当作真实运动。
- B 的较稳定原地自旋段：中心水平加速度RMS约0.9447 m/s²，537帧中520帧 `gate=2`；高速自旋有效帧仅30/793。KF与轮速贴合大多来自拒绝后的回退，不能作为融合已可靠的证据。
- B 的平移速度提高已有分配和实车证据。较平稳移动的轮速方向平均偏差约−0.315°，绝对偏差95%分位约4.14°；这不能代替地面轨迹，也不足以支持重新盲调固定偏角或相位提前。
- 两组均为SHADOW，`cmd_g=ref_g`，KF候选补偿没有进入实际四轮参考。实车剩余偏移不能直接归因于KF主动追加。

## 2. 本次代码修改

### 2.1 窗口内立即检查冲突

原来约每250 ms比较一次 `积分(a)-轮速Δv`，窗口未完成时继续沿用上一个窗口的通过状态。现在在有新鲜联合观测时检查当前窗口前缀，二维残差超过0.04 m/s立即拒绝，不等窗口结束。

短前缀即使残差很小也不能首次放行。启动、时基/源失效或冲突恢复时，必须先完成一整个250 ms一致窗口，再获得20次有效联合观测。冲突后重新建窗，不能凭几个好样本立即恢复。

### 2.2 检查融合后速度与轮速的分歧

加速度更新能通过速度/加速度交叉协方差影响速度，单靠积分前缀仍可能来不及拦截。现在每次获得新轮速后，检查融合后的速度与轮速重建速度之差；二维幅值超过 `velocity_innovation_max=0.04 m/s` 时，同周期撤销融合和主动补偿权限，取消该帧加速度观测标志，从**实测轮速**重建诊断滤波状态。

该阈值为保守工程初值，不是已标定的最优参数，也不是打滑判据。冲突无法确定IMU或轮速谁更接近地速；回退仅表示当前不足以批准完整融合。零摇杆不会把运动中的轮速强制清零，真实且一致的减速仍可融合。

### 2.3 限制姿态EKF强制重力重捕获

原姿态EKF在重力卡方检验连续失败后，只要低角速度和加速度模长接近g，累计超过50次便可强制恢复加速度修正。水平加速度1.5 m/s²叠加重力时，模长只增加约0.114 m/s²，仍落在原稳定判据内；云台稳定时低IMU角速度也不能证明底盘没有自旋。

新增 `IMU_QuaternionEKF_SetGravityRecoveryAllowed()`。强制重捕获启动必须有独立静止许可、原稳定判据、IMU角速度小于0.05 rad/s及连续500 ms确认，确认时间按真实dt累计。条件中断清除资格计时；强制恢复期间静止许可撤销时阻止继续强制修正。

本工程在INS任务中复用 `INS_SetChassisStill()`：仅不跟随速控零命令、四轮在线且原始/滤波轮速静止时给出许可，许可年龄不得超过20 ms。自旋、跟随、力控、车轮运动或信息过期均不能批准该强制路径。正常启动、陀螺预测和通过检验的重力更新继续运行。

独立移植姿态库时，应由平台每周期提供可靠许可；缺省关闭的是连续拒绝后的强制重捕获。独立静止许可仍不是外部地速传感器，锁轮滑动等情况需要额外信息识别。

## 3. 日志和接口

历史 `ChassisMotionState` 仍为444字节，MCL1二进制帧仍为456字节。新增信息位于同帧OBS诊断，不改变公共底盘命令协议。通道0保持约10 Hz完整七行输出，没有提高完整文本频率。

| OBS字段 | 含义 |
| --- | --- |
| `dv_now_mmps=x,y` | 当前一致性窗积分残差；只在新鲜联合端点更新，拒绝后重建窗时归零 |
| `dv_res_mmps=x,y` | 最近一次完整窗口或冲突事件留下的积分残差 |
| `v_res_mmps=x,y` | 融合后速度减轮速速度；在新轮速时更新，触发回退时保留触发前差值用于诊断 |
| `reject_reason` | 0无拒绝原因；1窗内积分残差；2完整窗口积分残差；4融合后速度差 |
| `gate` | 0建窗；1通过；2冲突；仍需结合恢复样本和源端有效性判断 `valid` |
| `rejects` | 拒绝事件累计，包含提前拒绝与融合速度拒绝；不可直接与frame14的完成窗口拒绝次数比较 |
| `att_flags` | 保留旧位；新增32=独立静止许可允许强制恢复，64=正在强制重捕获。它是位掩码 |

`reject_reason` 会保留到成功完成窗口或一致性状态被重置，不一定只在触发瞬间出现。低频日志可能漏掉具体触发帧，应结合 `rejects` 增量和连续时间判断。回退后的KF与轮速接近也不代表独立验证成功。

移植配置新增正数 `velocity_innovation_max`，建议先调用 `ChassisMotionConfigDefault()` 再覆盖参数。解析器对frame15强制要求三个新字段，并保留历史frame14等日志兼容性。详细接口见[移植说明](../卡尔曼底盘移植与接口.md)。

- 5 ms合成松杆失配测试在四方向/各相位均于50 ms内撤销权限，未放行超过阈值的反向估计；原代码会使该测试失败。这是独立构造的动态轨迹测试，**不是用10 Hz实测日志精确重放**，50 ms不是实车保证值。
- 姿态库在1/5/10 ms周期下均阻止无许可动态强制修正，静止许可后的强制恢复启动约为0.501/0.505/0.510 s；中断确认计时测试通过。

## 7. 下一次实车操作

1. 烧录新版后，在通道0确认 `fw=20261108 frame=15 mode=2`。先不跟随静置5～10秒，云台保持不动，让恢复确认完成。
2. 不跟随模式分别前进/后退/左右运动后松杆，各做3次；单次移动约2秒、松杆后等3秒。记录实车是否反窜、滑行和方向偏移；重点看松杆附近 `valid`、`gate`、`dv_now_mmps`、`v_res_mmps`、`reject_reason`。
3. 小陀螺先原地自旋约5秒，再分别前后左右平移各约2秒，中间松杆保持自旋约3秒；最后退出自旋静置5～10秒。云台朝向和俯仰尽量保持固定，保存完整通道0日志。
4. 用地面直线或同步视频记录平移的实际偏移方向/距离。发生J-Link断连或暂停时标记动作时刻，不把断连两侧当作连续窗口。

优先判断冲突是否被及时拦截，以及稳定自旋的加速度残差是否下降。新版门控更严格，融合有效率可能先降低；这本身不表示退化，也不能用提高通过率替代观测精度验证。在这些检查通过前继续SHADOW，不开启主动KF补偿。
