## 1. 上电行为与启用顺序

当前默认 `MC_SHADOW`、`MC_IMU_ACCEL_VALIDATED=1`。后者仅表示允许加速度进入估计 KF，不能据此宣称完成实车标定。源端运动观测恢复后，先通过完整250 ms一致性窗，再积累20次有效联合观测，预期 `accel=1 obs=15 valid=1 exit=0`。冲突后重新执行整窗确认与样本恢复。影子模式按固定增益 0.1 计算候选 `dv_g`，实际始终 `cmd_g=ref_g`。显式切换主动模式后才可能 `cmd_g=ref_g+dv_g`；急停/输出禁止时四轮立即归零。

普通摇杆回中仍保持电机使能，基础速度参考按斜坡降到零，由电机速度环请求减速；这与急停零电流不同。KF观测本身不产生制动力。当前未实现根据滑移自适应调整轮速观测可信度及牵引力控制，因此不能把估计开启等同于已经具备防滑功能。

完整的轮速 + IMU 四维 KF 和补偿分支已实现，但高速全工况尚未实车验收。当前先恢复可靠时基、姿态及四轮执行，再检查影子估计；转速调度模式尚未默认启用。保留真实估计，不以零摇杆/轮速硬清加速度。

模式由 `ChassisMotionSetMode()` 选择，建议从底盘任务的正常调试入口调用；没有占用键鼠、改变现有遥控开关，也没有新增自动驱动车辆的启动试验。

| 枚举/值 | 行为 |
| --- | --- |
| `MC_BASELINE` / 0 | SI 速度链运行，KF 不更新，补偿关闭 |
| `MC_ESTIMATE_ONLY` / 1 | 估计开启，实际轮速参考不含补偿 |
| `MC_SHADOW` / 2 | 默认模式；计算并记录候选补偿，实际输出仍为原参考 |
| `MC_ACTIVE_FIXED` / 3 | 显式开启后，固定 Kp=0.1，估计有效时作用于输出 |
| `MC_ACTIVE_SCHEDULED` / 4 | Kp 按实际轮速逆解的底盘转速调度 |

上电已选择 `MC_SHADOW`，无须额外调用。先确认姿态有限且稳定、四轮都有正常执行，再检查估计和真实运动的一致性；通过这些检查后才考虑显式开启主动模式。固定增益 0.1 不能当作最终最优参数。配置开关未放行、观测超时、协方差异常或恢复尚未确认时，即使选主动模式也不会追加补偿。

`BASELINE` 是新 SI 链的基线；与改动前旧固件的轨迹应分别记录。新链添加了斜坡和限幅，不能把不同参考波形当成同一 A/B 对照。

## 3. 单位、方向和安装必须核对

公共 `vx/vy/wz` 继续使用旧命令单位。速控内部平移使用 m/s、角速度使用 rad/s、转子参考仍为 °/s。平移旧单位乘 `MC_LEGACY_V_SCALE`；旧旋转策略乘 `MC_LEGACY_W_SCALE`。后者根据旧旋转列与新 SI 力臂换算，保留当前跟随、小陀螺策略的稳态轮速量级；旧 `wz=4000` 不能解释为 4000 °/s。

以 frame16 的72.5 mm半径（当时记录的外径145 mm）、19减速比为例，6000 °/s转子速度约为0.399589 m/s轮缘速度。此前frame≤15按60 mm计算，同转子速度对应0.330694 m/s；历史日志须保留旧标定。每轮半径与编码器方向可独立配置。顺序固定为 LF=1、RF=4、LB=2、RB=3。当前驱动四轮均为 `MOTOR_DIRECTION_NORMAL`；如果调整逻辑方向，应在 `MC_ENCODER_SIGNS` 中统一反馈与参考，避免再在驱动反转一次。

默认 J 保留原 X 轮代数平移方向，并采用文档示例的 SI 旋转力臂。它是待核验初值，轮子名称不能证明实际位置/滚动方向正确。S01/S02 如发现不同，修改 `MC_J_ROWS`；正解与逆解自动共用新 J，秩不足时该链不输出。

固定 N 为 INS 导航系 `(x,-y,-z)`。姿态 B/G 使用右手坐标；旧遥控命令和 J 则保留历史代数定义。第十三次前后移动支持 X 按传感器 +x 的水平航向投影，故 `MC_IMU_HEADING_OFFSET_RAD=0`；物理安装杆臂的前方仍沿传感器 -x，二者不能混为同一前向。第十四次落地侧移显示 J 逆解的 Y 与姿态 B 的 Y 相反，故先将旧代数平移 `(vx,vy)` 转为姿态 B 的 `(vx,-vy)`，再执行 `R(psi_BN)` 投影。不能在固定 N 内直接翻 Y。

估计返回旧命令坐标的正确逆链为 `hat_g = R(+theta_BG) * S * R(-psi_BN) * v_N`，其中 `S=diag(1,-1)`，等价于 `S*R(-psi_GN)*v_N`。`hat_g/user_g/ref_g/error_g/dv_g/cmd_g` 均属旧命令坐标，`wheel_b/wheel_n/x` 属右手姿态 B/N。输出应为 `J*R(-theta_BG)*cmd_g`：因为旧代数 Y 已反射，旋转满足 `S*R(theta)*S=R(-theta)`，不能直接使用右手相对角的正号。入口 `theta_BG=-offset_angle`，故该输出恢复原框架 `R(offset_angle)` 的方向。frame=3/4 的正反变换虽互逆，但漏掉这一物理方向约束，非零相对角时会让世界平移方向绕转；frame=5 同步修正两处。公共 INS、编码器符号和轮速投影不变。主机覆盖多航向、连续自旋、±pi 跨界、估计/影子/主动三模式；用户已确认小陀螺单独测试正常，但第十七次文件可见段不含持续自旋数据，应区分用户观察与日志证据。

`theta_BG` 仅使用真实相对 yaw；平台入口用 `MC_YAW_ENCODER_SIGN=-1` 将当前编码器角转换为模块正方向（2026-10-25 只动 yaw 的实车日志确认两者反向）。公共 `offset_angle` 和原跟随控制器仍保留旧符号。`CHASSIS_CMD_DIR_TRIM_DEG` 只旋转用户意图，不进入姿态重建。若 IMU 在底盘上，置 `MC_IMU_ON_GIMBAL=0`，由底盘姿态重建 G 朝向。

`MotionAccel_n` 继续作为补偿前诊断。`MC_IMU_FOLLOWS_PITCH=0` 时保留平面杆臂模型；当前 A 板随 pitch 运动且两轴相交，设为 1。INS 在同一采样帧计算 `alpha_b×r_b + omega_b×(omega_b×r_b)`，先从姿态 EKF 的加速度观测扣除，再去重力、以 8.5 ms 时间常数低通并用完整四元数投影，杆臂只扣一次。10 月 30 日起，用最近不超过 20 ms、最多 21 个实际时间戳的角速度二次拟合，在当前端点求导，降低 1 ms 两点差分的量化及读取抖动噪声；短窗未建立时使用两点差分，超时/异常重建历史。底盘只读取校正后的同帧快照。轴交点相对底盘中心的独立偏置仍按平面底盘运动校正。若转轴不相交或存在其他相对运动，需要另建机构模型。

2026-10-26 用户确认：A 板随 pitch 转动，IMU 在两轴交点前方约 8.4 cm、上方约 3.7 cm；10 月 30 日进一步确认测量终点是 MPU6500 芯片中心。图中 +x 是跟随正前方、+y 向右，模块 +z 向下，中位杆臂为 `(0.084,0,-0.037) m`。第四次日志中上抬停稳后 raw_a_x 从约 +0.33 变为 -3.90 m/s²，支持 INS 机体系 x后/y右/z上；因此保留 `MC_IMU_LEVER_SENSOR_X/Y/Z_M=(-0.084,0,+0.037)`。杆臂必须与 `imu_q`、`imu_gyro_rad` 同系，现有稀疏日志不能排除小的横向偏置或安装角误差，也不能据此替换实测尺寸。轴交点相对底盘参考中心的偏置仍由 `MC_YAW_CENTER_X/Y_M` 单独表达。

即使 `MC_IMU_ACCEL_VALIDATED=0`，也计算候选中心加速度并记录为 `center_a_mmps2`，但不加入 KF；`accel=0`、`obs=5`、`valid=0` 仍是预期行为。IMU 文本新增 `corr`：1 表示本帧满足新鲜样本、合法四元数、差分时间与角加速度等校正条件；0 表示本帧不能作为校正验证值。`corr=1` 仅表示计算条件满足，不表示实车标定已通过。未校正模块 N 系水平加速度是 `(nav_a_mmps2[0],-nav_a_mmps2[1])`，不要直接用原 INS 的 y 符号比较。

## 4. KF、有效性与退出

状态顺序为 `[vx, ax, vy, ay]`，位于固定 N 系。使用现有 `KalmanFilter_t`，启动分配一次，周期内不分配。F/Q 使用实测 dt；Q 为连续白 jerk 模型 `q*[[dt³/3,dt²/2],[dt²/2,dt]]`。R/P 为方差，不是标准差。

当前云台随 PITCH 安装分支，`R_ax=0.04+0.04*(sum(clamp(omega_imu_i,±40)^2)+clamp(omega_b,±40)^2)`，`R_ay` 同式；`omega_imu` 为 INS 三轴实测 rad/s，`omega_b` 为轮速逆解的底盘实际角速度。转动越快，中心加速度权重越低，轮速观测保持原方差。非有限 IMU 角速度拒绝加速度观测；不以零摇杆/零轮速硬置加速度为零，因而仍能观测实际平移。此权重是保守工程初值，不是从本车噪声完成辨识的最优参数。

关闭库中把零值当无效的自动观测机制。每周期重填量测；缺失/重复观测通过 H 零行屏蔽且保留正 R。全部缺测时只预测，停止命令也不会把真实滑行估计强行清零。运动中启动从新鲜轮速初始化，不假定静止。

当前初始阈值：观测年龄不超过 20 ms，轮间和轮/IMU 时间差不超过 10 ms；预测 dt 为 0.5～20 ms。超周期重建状态并撤销补偿，不把长暂停替换成 5 ms。轮速观测缺失时最多保留 100 ms 的惯性可信窗口，速度方差超过阈值也退出；重新通过完整一致性窗并获得20次有效联合观测后才恢复主动补偿。

frame15在250 ms窗内逐次检查 `积分(a)-轮速Δv`，二维幅值超过0.04 m/s立即拒绝；融合后速度与新鲜轮速速度差超过 `velocity_innovation_max=0.04 m/s` 也撤销权限，并从实测轮速重建诊断状态。该处理不判定静止或打滑，运动中的轮速不会因零摇杆被强制清零。独立姿态EKF的连续拒绝强制重捕获还需要底盘新鲜静止许可、IMU角速度小于0.05 rad/s及连续500 ms确认；正常启动和通过重力检验的更新继续运行。

`observation_mask` 的位 0～3 对应 vx、ax、vy、ay；`wheel_valid_mask` 位 0～3 对应 LF/RF/LB/RB。创新字段只有相应观测位为 1 时才有意义。未使用加速度时 `accel_used=0`。

| `exit_reason` | 含义 |
| --- | --- |
| 0 | 正常 |
| 1 | 输出/估计模式关闭 |
| 2 | 预测周期异常 |
| 3 | 姿态或相对角/命令时效不满足 |
| 4 | 无可信轮速初始化，或惯性窗口超时 |
| 5 | IMU 未标定放行、无效或超时 |
| 6 | 速度协方差超限 |
| 7 | 矩阵运算/状态/协方差数值异常 |

## 5. 输出约束

原始参考与补偿各自做向量限幅和按真实 dt 的斜坡；不会把上一周期补偿参考再次累加。误差为 `ref-hat`，调度使用轮速逆解的实际底盘转速；云台陀螺和旧 `wz` 不替代底盘转速。

先对用户目标做轮速可行性处理，再计算误差。现车配置 `MC_WHEEL_LIMIT_ROTATION_PRIORITY=0`，所有模式统一缩放以保持请求运动比例；通用内核 `ChassisMotionConfigDefault()` 的保守初值仍为 `rotation_priority=1`，由工程适配层覆盖。设为1时仅 `CHASSIS_ROTATE` 小陀螺模式优先保持可行旋转参考，再按剩余轮速空间缩小平移；若纯旋转本身超限才缩小旋转。旋转优先策略会牺牲小陀螺下的平移速度，不提高 `MC_WHEEL_MAX_DPS`。上次执行轮速缩放或电流饱和会压低/撤去外层追加权限。模式变化清除旧补偿，失效立即退出主动补偿；原有急停、电机离线和命令超时仍优先禁止输出，退出速控会清除补偿/局部参考。

速控最终电流在驱动浮点转 int16 之前限制为 ±8000 raw，并记录请求及装入 CAN 缓冲区的值；停止时镜像为 0。镜像表示软件发送内容，不表示 CAN ACK 或实测电流。反馈电流仍从电机报文单独记录。

当前四轮注册表尚未接入正式裁判功率控制，因此 `power_limit_active=0`。本实现没有把电流保护或 `SetPowerLimit()` 的调用声称为已实现整车功率闭环。

## 6. 文本日志查看

当前仅启用 RTT 上行通道 **0**，名称 `ChassisMotion_Text`，直接输出可读 ASCII 文本。用原来的 RTTClient 或 RTTViewer 查看通道 0 即可，不需要二进制采集工具或解码。通道 1 摩擦轮 JScope 的初始化/发送、通道 2 文本缓冲注册及 IMU/拨盘/卡弹/通用文本日志仍通过 `#if 0` 暂时屏蔽，保留原代码便于恢复。

底盘任务只向 8 帧环形队列复制快照，低优先级任务将快照格式化为七行文本，整组非阻塞发送到 4096 字节 RTT 缓冲。满时整组丢弃，不阻塞控制任务。3072字节格式化缓冲区放在静态区，未启用浮点 printf 库；日志任务栈为 512 words（2 KiB），为整数格式化调用链留出空间，实车仍需检查栈高水位。默认 `MC_LOG_DECIMATION=20`，每 20 个控制周期输出一组，约 10 Hz；0 关闭。文本字段较多，建议保持该默认频率。

同一组七行带有相同的 `seq`，各数组以逗号分隔。YAW 为读取时的独立最新快照，应结合其 cmd_t_us、enc_t_us 使用：

| 行前缀 | 主要内容 |
| --- | --- |
| `[STATUS]` | 时间戳、模式、估计有效位、退出原因、加速度融合位、轮速/观测掩码、周期、IMU/命令年龄、队列丢帧 `qdrop`、发送丢组 `tdrop` |
| `[WHEEL]` | 四轮反馈/有效参考转速、发送/反馈电流、轮速逆解的 N 系速度、实际底盘角速度和 `omega_ref_mradps` 旋转参考 |
| `[IMU]` | 本帧校正候选有效位 corr、云台相对底盘 yaw、底盘/云台航向角、三轴角速度、未去重力加速度、原 INS 导航加速度和校正后的中心加速度 |
| `[KF]` | N 系估计速度/加速度，旧命令 G 系用户输入 `user_g_mmps`、参考/估计/误差/补偿/最终速度，增益和限幅/电流饱和标志 |
| `[YAW]` | diag=2，输入、目标/反馈、完整精度编码器、温度与启动标定；trim_z_urps 为额外零偏，trim 为学习状态，trim_updates 为更新次数 |
| `[DIR]` | 真实/输出相对角、相对角速度、提前量及方向提前有效位 |
| `[OBS]` | 时基/IMU恢复、姿态/重力、量测方差、一致性门控；frame15增加当前窗内残差 `dv_now_mmps`、融合后速度差 `v_res_mmps` 和拒绝原因 `reject_reason` |

`fw=20261028` 起新增独立的约1 Hz诊断包 `[RIGID]`、`[AID]`，当前还包含 `[CLOCK]`，仍在通道0输出文本，主帧默认约10 Hz。`RIGID` 在INS全采样频率累计刚体补偿项、补偿前后加速度的RMS/均值、峰值及采样间隔；`AID` 累计各项学习门槛的失败次数，保留低频日志间隙内短暂失败的证据。两行以 `win` 关联，含各自时间；不要把 `win` 当作主帧的 `seq`。`CLOCK` 为独立时基摘要。诊断包整包非阻塞发送，丢失另计 `ddrop`。`MC_LOG_DECIMATION=0` 只关闭主帧队列，秒级诊断继续运行。

原因位和整数统计可用下列脚本转成中文摘要；详细字段、坐标系及采集步骤见 `调试记录/20261028_INS补偿与零偏学习诊断说明.md`。

```powershell
python tools/analyze_imu_diagnostics.py "通道0日志.txt" --json "诊断结果.json"
```

字段后缀即单位：`mmps` 为 mm/s，`mmps2` 为 mm/s²，`mrad` 为毫弧度，`mradps` 为毫弧度/秒，`dps` 为电机轴度/秒，`us` 为微秒。`kp_x1000` 是增益乘 1000；电流保持 DJI 原始单位。例如 `ref_g_mmps=500,-250` 表示 G 系参考速度 `(0.500,-0.250) m/s`。四轮顺序固定为 LF/RF/LB/RB，三轴顺序为 xyz，平面向量顺序为 xy。文本转换取整数，非有限值用 `-2147483648` 标记，不应当作真实测量值。

当前默认已放行加速度估计融合，通过一致性窗和恢复样本后应为 `accel=1 obs=15 valid=1`，输出允许时 `exit=0`；默认 `mode=2` 计算候选补偿，实际 `cmd_g=ref_g`。有效且未受执行限制时 `kp_x1000=100`；frame17 在 `control_ready=0` 时保持 `dv_g=0`，获准后按渐入比例和误差变化。只有显式切换主动模式且 `control_ready=1` 才可能 `cmd_g=ref_g+dv_g`。三个字段独立转换成整数，因此逐轴比较文本时允许约1 mm/s的截断差；小于1 mm/s的补偿打印为0是正常现象。关闭输出时 `exit=1` 可以与 `valid=1` 同时出现，表示电机权限关闭、估计仍有效，实际参考已清零。发送电流镜像来自最近一个电机控制周期，与本周期轮速参考需按任务延迟比较。

frame15的 `reject_reason`：0无拒绝原因、1窗内积分残差、2完整窗口积分残差、4融合后速度差。`rejects` 从本版开始累计拒绝事件（含提前拒绝），不能直接与frame14的完成窗口拒绝数作通过率比较。`att_flags` 新增32=独立静止许可、64=强制重力重捕获中。字段细节与使用边界见移植说明。

`nav_a_mmps2` 来自原 INS 导航系，`center_a_mmps2` 来自已变换并校正后的模块 N 系，二者不能直接逐轴相减。`raw_a_mmps2` 实际为安装修正后、尚未去重力的 INS.Accel，不是 ADC 计数。

`time_us` 对应文本中的 `t_us`，约71.6分钟回绕，主机分析需展开，MCU年龄判定已按无符号差值处理。完整状态保存在 `ChassisMotionState`，新增观测诊断另保存在 `ChassisMotionObservationState`；当前OBS也输出四元数、方差与创新用于核对，不改变历史444字节状态布局和456字节二进制帧。

旧的 MCL1 二进制帧定义和解码器保留供历史日志使用，**不适用于当前文本日志**。仅在解码以前保存的二进制文件时运行：

```powershell
python tools/decode_chassis_motion.py motion.bin motion.csv
```

可以用 `ChassisMotionGetState()` 获取最新状态，或从调试器观察模块静态 `s`。日志队列只允许一个消费者；已由日志任务消费时，不要再添加第二个 Pop 消费者。
